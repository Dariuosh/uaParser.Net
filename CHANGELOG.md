# Changelog

## 2.0.0 (not released yet)

A rewrite. The rules are now generated from ua-parser-js 1.0.41 and give the same results as
ua-parser-js, field by field. The namespaces (`uaParserLibrary`, `uaParserLibrary.Models`,
`uaParserMiddleware`) and the `UAParser` methods keep their names, but results and the
ASP.NET Core setup have changed; see "Upgrading from 1.x" below.

### Added

- Every rule of ua-parser-js 1.0.41 (200 rules, 307 regexes), generated by
  `tools/RuleGenerator` instead of ported by hand, including rarely used browsers, devices and
  operating systems that 1.x did not have.
- Tests that compare every field with what ua-parser-js returns for 1,378 user agents, and
  ua-parser-js's own 1,217 test expectations.
- `ClientInfoCache`: a thread-safe, bounded cache for repeated user agents.
- `ClientInfo.UserAgent`: the user agent the result was read from.
- `DeviceTypes`: constants for `Device.Type`.
- `uaParser.Net.AspNetCore` package, the middleware's first release on NuGet: a scoped
  `ClientInfo` for the current request, `HttpContext.GetClientInfo()`, and
  `AddUAParser(o => o.CacheCapacity = n)`.
- `uaParserBenchmark` project and `npm run bench`, to measure speed on any machine.
- XML documentation, Source Link and a symbol package.

### Changed (breaking)

- A missing value is `null`. 1.x returned `"Other"`, `"UnKnown"`, `""` or `"undefined"`.
- Results are immutable records (`Browser`, `CPU`, `Device`, `Engine`, `OS`, `GPU`,
  `ClientInfo`) instead of classes with setters and an `Empty` property.
- Names follow ua-parser-js 1.0.41, for example `Samsung Internet` (was `Samsung Browser`),
  `EdgeHTML` (was `Edge HTML`).
- ASP.NET Core: `ClientInfo` is registered as scoped and holds the current request's result.
  1.x registered one singleton `ClientInfo` that every request overwrote.
- `AddUAParser()` takes an optional `Action<UAParserOptions>`. `Options`, `OptionBuilder` and
  `IOptionBuilder` were removed.
- .NET 10 (was .NET 5).

### Removed

- The public `BrowserExpressions`, `CPUExpressions`, `DeviceExpressions`, `EngineExpressions`,
  `OSExpressions`, `GPUExpressions`, `*Match` classes and `Util`. The rules are internal now.
- The `uaParserResource` assembly (`DeviceType`, `Keywords`, `Vendors`).

### Fixed

- Wrong results when several threads parsed at the same time: 1.x reused the same result
  objects between calls.
- ASP.NET Core: 1.x parsed the user agent after the rest of the pipeline had run, so the
  request's own handlers saw the previous request's values.
- Results that differed from ua-parser-js, for example an empty `Browser.Major` for `WAP2.0`
  (now `2`). Regexes now match as in JavaScript (`\d` and `\w` match ASCII characters only).
- A `null` user agent threw an exception; now every value is `null`.
- Very long user agents: at most the first 500 characters are read, as in ua-parser-js, and every
  regex has a time limit.

### Upgrading from 1.x

| 1.x | 2.0 |
|---|---|
| `if (browser.Name == "Other")` | `if (browser.Name is null)` |
| `device.Type == "mobile"` | `device.Type == DeviceTypes.Mobile` (same value) |
| `browser.Name = ...` | `browser with { Name = ... }` |
| `services.AddUAParser(options => ...)` | `services.AddUAParser()` |
| `app.UseUAParser()`, then inject the singleton `ClientInfo` | Inject `ClientInfo` (scoped), or call `HttpContext.GetClientInfo()`; `UseUAParser()` is optional |
| `Samsung Browser`, `Edge HTML`, ... | `Samsung Internet`, `EdgeHTML`, ...: compare names with the ua-parser-js 1.0.41 list |

## 1.0.1 (2021-06-04)

- Port of a subset of the ua-parser-js rules to .NET 5: `UAParser.GetBrowser`, `GetCPU`,
  `GetDevice`, `GetEngine`, `GetOS`, `GetGPU` and `GetClientInfo`.
